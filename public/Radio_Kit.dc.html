Developer Story

Building Radio_Kit v1.0.0

01 The Spark
The Spark: Radio Without an RF Chip

Nearly every embedded wireless project follows an identical playbook: you pick an external RF transceiver like an SX1262 LoRa module or CC1101, wire it over SPI, configure registers, and treat RF synthesis as an opaque black box.

One evening while reading the RP2040 datasheet, I stopped at the clock generator block diagram. Microcontrollers spend millions of clock cycles synchronizing internal buses, but the RP2040 includes auxiliary clock outputs capable of routing fractional clock dividers directly to physical pins. That made me ask an unconventional question:

"Can I turn the microcontroller's raw silicon clock tree into an autonomous, encrypted RF transmitter with zero external radio silicon?"

What started as a rough experiment to see if an oscilloscope could detect a square wave on GPIO21 grew into Radio_Kit v1.0.0: a production-grade, dual-core bare-metal Ada framework capable of continuous-phase 2-FSK telemetry, FM voice transmission, automated CW beacons, ChaCha20 encryption, and hardware watchdog crash diagnostics.

02 Clock Synthesis
Synthesizing RF from the RP2040 Clock Tree

To create an RF carrier without an analog oscillator, you have to manipulate the RP2040's phase-locked loops and clock multiplexers. The RP2040 features four auxiliary General Purpose Clock Outputs (GPOUT0 through GPOUT3) mapped directly to silicon pads:

GPIO21 → GPOUT0
Independent clock generator with 16-bit integer and 8-bit fractional divider.
GPIO23 → GPOUT1
Secondary carrier or reference channel for dual-channel operations.
GPIO24 → GPOUT2
Direct silicon clock generator channel.
GPIO25 → GPOUT3
Fourth GPOUT generator output, co-located with user LED circuit.

I lock PLL_SYS to a clean 90 MHz reference derived from the 12 MHz external crystal oscillator. Feeding this 90 MHz source into the GPOUT clock divider gives me fine-grained control over the output carrier:

MATHEMATICAL SYNTHESIS PIPELINE
12 MHz XOSC → PLL_SYS (90 MHz) → [INT: 16-bit + FRAC: 8-bit / 256] → GPIO Pad
F_carrier = 90,000,000 / (Integer_Div + Fractional_Div / 256.0)

By dynamically recalculating and updating these divider registers in real time, I can synthesize frequencies from 1.374 kHz all the way to 45 MHz with sub-kilohertz resolution.

03 Dual-Core AMP
The Dual-Core AMP Engine

In early prototypes, I tried running everything on a single ARM Cortex-M0+ core. It was a disaster: whenever the CPU handled sensor polling, ADC sampling, or packet formatting, the modulation loop suffered microsecond-level jitter, causing RF spectral broadening and packet corruption.

To solve this, I redesigned Radio_Kit into a true Asymmetric Multiprocessing (AMP) engine utilizing both RP2040 cores:

Core 0: Appliance Supervisor
Handles ADC temperature and battery voltage sampling, cryptographic encryption, framing, watchdog maintenance, and state sequencing. It feeds transmission commands to Core 1 via hardware FIFOs.
Core 1: Dedicated Waveform Synthesizer
Runs in a zero-overhead, interrupt-free cycle with cycle-accurate timing. It reads commands from SIO FIFO, drives GPOUT fractional dividers, and modulates phase continuously with zero jitter.

Communication between cores happens across the RP2040's hardware SIO.FIFO with lock-free, zero-copy atomic message passing. Even during heavy cryptographic encryption on Core 0, Core 1 never drops a single RF clock cycle.

04 Modulation Suite
Continuous-Phase 2-FSK, FM Audio & CW Beacon

An unmodulated carrier is just a spike on a spectrum analyzer. To make Radio_Kit transmit actual data, voice, and telemetry, I implemented three distinct modulation engines in Ada:

2-FSK at 1200 Baud
Frequency shift keying between Mark (e.g. 27.120 MHz) and Space (27.125 MHz) frequencies with phase continuity to prevent spectral splatter.
Real-Time FM Voice/Audio
Direct frequency modulation from ADC audio samples at 8 kHz, modulating clock dividers proportional to voice amplitudes.
20 WPM PARIS Morse Beacon
Automated continuous wave (CW) on-off keying adhering to standard amateur radio PARIS timing standards (60ms dit element).

The 2-FSK engine uses precomputed divider lookups to transition between Mark and Space frequencies without pausing the clock generator, preserving phase continuity across bit boundaries.

05 Security & Framing
Protocol Framing, Table-Driven CRC-16 & ChaCha20

Transmitting over the air means dealing with noise, false triggers, and security. I designed a structured packet framing layer to guarantee data integrity and confidentiality:

RADIO_KIT ON-AIR PACKET STRUCTURE
[0xAA 0xAA Preamble] → [0xD391 Sync Word] → [Seq_ID: 16-bit] → [Len] → [ChaCha20 Encrypted Payload] → [CRC-16-CCITT]

The integrity of each frame is verified using a table-driven CRC-16-CCITT (polynomial 0x1021), precalculated into flash memory to save CPU cycles.

For security, I implemented a pure Ada bare-metal port of the 256-bit ChaCha20 stream cipher. Nonces are dynamically generated from rolling packet sequence counters, and receivers maintain an anti-replay sliding window to reject replayed or injected packets.

06 Hardware Health
Die Temperature, Voltage & Crash Telemetry

Because driving clock generators at maximum slew rate and current draws noticeable power, I built an integrated Hardware Health Guardian directly into the runtime:

Die Temp Monitoring
Samples the RP2040 internal silicon temperature sensor via ADC Channel 4. Automatically throttles RF duty cycle if die exceeds 65°C.
Vsys Brownout Detection
Samples system supply rail via ADC Channel 3 to detect battery sag or brownout risks before transmission begins.
Scratchpad Post-Mortem
Preserves crash reason, fault address, and watchdog state across warm reboots in hardware registers SCRATCH0..SCRATCH3.
RF Time-Out Timer (TOT)
Hard hardware safety interlock that unconditionally kills carrier generation if any transmission exceeds 15 seconds.

Every telemetry burst includes real-time die temperature, system voltage, and transmission counters, allowing ground stations to track physical silicon health continuously.

07 Harmonics & RF
Managing Digital Harmonics & Drive Strengths

Because the RP2040 outputs a digital square wave rather than a pure analog sine wave, the signal naturally contains energy at odd harmonics (3f, 5f, 7f, ...). Transmitting unfiltered square waves directly into an antenna is bad engineering and violates spectrum regulations.

To address this, Radio_Kit provides direct low-level control over the RP2040 pad electrical characteristics:

Programmable Drive
Configure output current to 2mA, 4mA, 8mA, or 12mA to match load impedance and reduce harmonic radiation.
Slew Rate Limiting
Toggle between Fast and Slow slew rates to soften square edges and suppress high-frequency harmonic spurs.
Dummy Load Testing
All bench testing is conducted into a 50-ohm terminator and low-pass Pi filter to verify RF emissions safely.

Combining pad slew control with a simple external low-pass filter converts the digital clock into a clean, compliant RF carrier.

08 Master Appliance
The 24/7 Master Demonstration Appliance

To prove the rock-solid reliability of the architecture, I built a complete autonomous radio beacon application in examples/radio_kit_demo/src/radio_kit_demo.adb. When powered on, the RP2040 boots into an autonomous 24/7 transmission cycle:

Ada (examples/radio_kit_demo/src/radio_kit_demo.adb)
procedure Radio_Kit_Demo is
   -- Core 0: Initialize hardware health, ADC, crypto keys, and launch Core 1
   Health.Initialize;
   Dual_Core.Launch_Core1;

   loop
      -- 1. Read on-chip die temperature and system supply voltage
      Health.Sample_Sensors (Die_Temp, Vsys_Volts);

      -- 2. Transmit 20 WPM PARIS CW Morse Beacon on 27.120 MHz
      Waveform.Transmit_CW (Callsign => "LP-RP2040", Speed_WPM => 20);

      -- 3. Transmit ChaCha20-encrypted 2-FSK telemetry packet at 1200 baud
      Telemetry_Payload := Format_Telemetry (Die_Temp, Vsys_Volts, Packet_Seq);
      Crypto.Encrypt (Telemetry_Payload, Nonce, Encrypted_Payload);
      Waveform.Transmit_2FSK (Encrypted_Payload);

      -- 4. Kick hardware watchdog and sleep until next interval
      RP.Watchdog.Feed;
      Sleep_Until_Next_Cycle;
   end loop;
end Radio_Kit_Demo;

This demo has run continuously on physical hardware for days without a single memory leak, dropped packet, or watchdog reset.

09 Why Ada?
Why Ada 2022 on the Cortex-M0+?

People often ask why I wrote Radio_Kit in Ada instead of C or Rust. The answer comes down to domain modeling and spatial predictability.

In C, frequencies and clock dividers are passed around as raw uint32_t values. A typo or integer overflow can silently write an out-of-range divider into clock hardware, instantly freezing the RP2040 system bus. In Ada, I define strong scalar types:

type Frequency_Hz is range 1_374 .. 45_000_000;
type Integer_Divider is range 1 .. 65_535;
type Fractional_Divider is range 0 .. 255;

The compiler mathematically enforces these constraints at compile time under the light-cortex-m0p runtime profile. There are zero dynamic memory allocations, zero hidden heap calls, and zero compiler warnings.

10 Reflections
What Building Radio_Kit Taught Me

Radio_Kit taught me that modern microcontrollers are far more capable than standard developer documentation suggests. When we limit ourselves to the generic vendor peripheral libraries, we treat silicon as an off-the-shelf appliance.

When you look closer at the underlying silicon blocks:

A PLL becomes a programmable frequency source.
A fractional divider becomes an RF synthesizer.
A dual-core inter-core FIFO becomes a zero-jitter modulation pipeline.
And Ada 2022 turns that silicon into an impenetrable, memory-safe transmission engine.

That is what engineering close to the metal means to me: understanding silicon so deeply that you can build reliable technology out of resources that others overlook.

VIBE CODING IN SILICON: ARCHITECTURE VS. AI ACCELERATION

Building Radio_Kit was a masterclass in modern vibe coding. I used AI as an intellectual sparring partner to brainstorm fractional clock divider formulas, format Morse code timing tables, and generate technical documentation.

Yet, the foundational architectural decisions—the dual-core AMP split, lock-free SIO FIFO IPC, continuous-phase 2-FSK divider updates, ChaCha20 crypto engine, and hardware watchdog crash telemetry—were entirely designed and implemented by me. The AI helped brainstorm and document; the physical silicon mastery and mission-critical code are mine.
