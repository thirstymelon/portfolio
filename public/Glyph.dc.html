Glyph

Bare-Metal 2D Embedded Graphics Framework

A zero-heap, deterministic 2D graphics framework written in Ada 2022 from the ground up for resource-constrained microcontrollers. Built on standard HAL buses with integer rasterization, Cohen–Sutherland line clipping, transparent tile streaming, and physical silicon validation.

The full story

01 Starting From Scratch
Why I Built Glyph From Scratch

In the embedded C and C++ ecosystem, developers take display libraries for granted. If you want to light up an OLED or TFT, you grab u8g2, LovyanGFX, or LVGL, wire up a bus, and start drawing buttons. But in the bare-metal Ada world, that tooling simply didn't exist.

When I decided to put graphics on microcontrollers using Ada, I could have written a thin C binding to wrap an existing library. But that would defeat the whole purpose. I didn't just want pixels on glass—I wanted to understand every layer of how display architectures actually work.

So I decided to implement every layer myself: the rasterization algorithms, clipping mathematics, packed memory buffers, display controller command state machines, and hardware bus transports. That decision transformed Glyph from a routine driver into an in-depth systems journey across mathematics, hardware timing, and memory design.

Integer Rasterization
Designing pixel-perfect geometry routines without floating point hardware.
Clipping Mathematics
Enforcing rigorous boundary guarantees so off-screen coordinates never corrupt memory.
Zero-Heap Allocations
Eliminating dynamic allocation entirely in favor of static composition with Ada generics.
Silicon Bus Bridges
Directly integrating standard HAL.I2C and HAL.SPI without messy board glue code.
02 Why Ada 2022?
Why Ada 2022 Fits Embedded Graphics

People often associate Ada with aerospace flight systems, railway signaling, and defense contracting. But those exact qualities—strong scalar typing, compile-time dimension validation, contract checks, and explicit resource lifetimes—make Ada phenomenal for bare-metal graphics.

In traditional C graphics code, a drawing function like draw_line(int x1, int y1, int x2, int y2, uint16_t c) has five naked integers. It is embarrassingly easy to invert arguments, pass negative dimensions, or trigger silent buffer overflows. In Ada 2022, coordinates, line bounds, and color types are distinct strong types. Passing an inverted axis or out-of-range integer is caught immediately at compile time.

Ada gives me zero dynamic allocation, deterministic frame times, and mathematically sound contracts without needing an operating system or garbage collector.
03 The Architecture
Decoupled Layered Architecture

One of my primary goals was preventing tight coupling between the graphics engine and physical controller silicon. A line-drawing algorithm should never know if it's talking to an I²C monochrome OLED or an SPI color TFT.

Glyph is structured into distinct, isolated layers using Ada generic packages:

LAYERED PIPELINE TOPOLOGY
Application → Display → Canvas → Algorithms → Framebuffer → Layout → Controller → Transport (HAL.I2C / HAL.SPI) → Physical Silicon
  • Display: Public-facing high-level API orchestrating initialization, canvas binding, and frame flushes.
  • Canvas: Primitive drawing operations, state management, and coordinate translation.
  • Algorithms: Pure mathematical algorithms (clipping, rasterization, sector inclusion) completely independent of hardware.
  • Framebuffer / Stream: Packed static memory arrays or streaming row formatters.
  • Controllers: Hardware command protocols for SSD1306 and ILI9341 display controllers.
  • Transport: Universal HAL bridges that communicate directly over hardware I2C or SPI buses.
04 Algorithms & Math
Mathematics of Pure Integer Rasterization

Because bare-metal microcontrollers like the Cortex-M0+ lack hardware floating-point units, every single geometric computation in Glyph is implemented with pure integer mathematics.

Before any line is drawn, it passes through Cohen–Sutherland line clipping. By calculating 4-bit integer outcodes for each endpoint, lines entirely within the viewport are drawn immediately, lines entirely outside are rejected in $O(1)$ time, and boundary-crossing lines are clipped cleanly without risk of writing outside buffer boundaries.

For curves and sectors, I implemented Midpoint Circle rasterization and an $O(1)$ 2D cross-product vector inclusion test. This allows Glyph to paint arbitrary angular pie wedges, arcs, and half-circles with zero trigonometry calls per pixel during the rasterization loop.

05 Memory & Streaming
Breaking the 153.6 KB Color RAM Barrier

Monochrome OLEDs (128×64) are easy on memory: a 1-bit packed array takes exactly 1,024 bytes of static RAM. But when I added support for the ILI9341 240×320 color TFT (16-bit RGB565), the math became daunting: $240 \times 320 \times 2 = 153.6\text{ KB}$ of RAM. That is larger than the entire internal SRAM of many microcontrollers!

To solve this, I designed three unified rendering modes behind a single API:

1. Full Framebuffer
153.6 KB RAM. Maximum rendering speed on boards with ample SRAM. Full arbitrary reads and writes.
2. Tile_Stream (15 KB)
Renders in 10 horizontal bands of 32 scanlines. Coordinates are translated automatically—user code requires zero offset math!
3. Direct_Stream (0 RAM)
Zero RAM framebuffer. Writes directly to the display controller window registers over high-speed SPI.

Crucially, I ran bit-exact validation tests between Tile_Stream and Direct_Stream to guarantee that low-RAM rendering produces identical pixel output to a full-sized framebuffer.

06 Silicon Bus Bridges
Standard HAL Bridges: Zero Custom Glue

Many embedded graphics libraries require writing cumbersome boilerplate to bridge the library to your board's physical I²C or SPI bus. In Glyph, I built directly on the standard Ada HAL (`HAL.I2C` and `HAL.SPI`) interfaces.

Because the transport layer accepts standard port pointers, Glyph works out-of-the-box across ARM Cortex-M (STM32, RP2040, nRF52, SAMD) and RISC-V. You configure your microcontroller pin muxing, initialize the hardware bus, and hand the port pointer directly to OLED.Init or TFT.Init without writing custom glue code.

07 Silicon Verification
Running Real-Time Animation on Physical Silicon

A graphics framework is only theoretical until it runs smoothly on real hardware. I targeted the Vicharak Shrike-Lite (Raspberry Pi RP2040) paired with an SSD1306 monochrome OLED over I2C0 and an ILI9341 color display over SPI0.

To push the engine, I wrote a real-time animated music player interface featuring a prominent rotating vinyl record, a swinging tonearm, crisp track typography ("Sailor Song" by Gigi Perez), and an animated progress scrubber driven by the hardware timer:

02with RP.I2C_Master;
03with RP.Device;
04with Glyph.Colors;
05with Glyph.Fonts;
06with Glyph.Display.SSD1306;
07
08procedure Example_Main is
09 -- Create static zero-heap OLED instance
10 OLED : Glyph.Display.SSD1306.Display_T :=
11 Glyph.Display.SSD1306.Create (Glyph.Display.SSD1306.Framebuffer);
12begin
13 -- Initialize RP2040 I2C0 directly via Ada HAL
14 OLED.Init (RP.Device.I2CM_0'Access);
15 OLED.Clear;
16
17 -- Draw animated geometry & typography
18 OLED.Paint_Rectangle (0, 0, 127, 63, Glyph.Colors.White);
19 OLED.Paint_Circle (64, 28, Radius => 14, Color => Glyph.Colors.White);

22end Example_Main;

The animation ran fluidly at steady frame rates with zero jitter, zero dynamic memory churn, and rock-solid stability.

08 Desktop Simulator
Headless Simulator & Multi-Format Video Export

Flashing physical microcontrollers over SWD or USB every time you tweak a coordinate or font spacing is slow and tedious. To accelerate development, I engineered a Headless Desktop Simulator with virtual I²C and SPI buses.

The simulator runs natively on macOS and Linux, executing the exact same Ada drawing algorithms and memory layouts as physical hardware. Even better, I added a multi-frame session recorder (Glyph.Simulator.Recorder) that captures frames and exports them directly into:

24-Bit Lossless BMP
Pixel-accurate single-frame snapshots for regression testing.
Palette-Optimized GIF
Compact animated previews perfect for documentation and GitHub pull requests.
H.264 MP4 Video
High-framerate video recordings of complex UI interactions.

10 Meaning & Takeaway
What Building Glyph Taught Me

Building Glyph convinced me that you never truly understand an embedded abstraction until you build it yourself without relying on someone else's library.

It forced me to think deeply about cache lines, bit manipulation, bus contention, and mathematical edge cases that high-level GUI libraries paper over. And it proved that modern Ada 2022 is an incredible, expressive tool for bare-metal systems when you need performance, deterministic memory, and safety.

Putting graphics on an embedded screen in Ada shouldn't require abandoning the safety of the language. Glyph makes high-reliability graphics feel native.
VIBE CODING & BARE-METAL REALITY

Throughout Glyph, I worked as a vibe coder—collaborating with AI tools (ChatGPT, AntiGravity, and Claude) to brainstorm rasterization approaches, explore trigonometric tradeoffs, and draft clear documentation.

However, AI cannot debug hardware SPI bus timings or predict memory bus contention on a Cortex-M0+. The architectural decisions, the zero-heap guarantee, the static tile streaming pipeline, and every line of Ada 2022 bitwise logic were conceived, architected, and implemented by me. AI provided the brainstorming velocity; human engineering delivered the bare-metal reliability.
